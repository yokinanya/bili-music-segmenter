# bili-music-segmenter

以 API 服务分析直播录像、定位完整单曲边界并导出演唱片段。支持浏览器上传，以及 yt-dlp 下载视频后自动合并、切片。全部操作通过 Material 3 工具操作中心完成，任务由 Python 服务持久执行。

需要 Python 3.12、uv、FFmpeg、Node.js 20 或以上。项目不再包含本地检测模型、TensorFlow 或 GPU 镜像。网易云识曲直接运行随项目打包的 JavaScript，无需单独启动 NeteaseCloudMusicApi。

## 启动

```bash
cp .env.example .env
# 填写 Gemini 配置
uv sync
uv run -m segment.webui
```

使用控制台打印的带令牌地址打开页面。服务默认仅监听 `127.0.0.1:7860`；可用 `--port` 修改端口。令牌每次启动更换，服务重启后请使用新地址。浏览器保存令牌并从地址栏移除；普通 API 必须通过请求头认证，试听和下载链接支持 URL 令牌。

根目录 `.env` 必填：

```dotenv
GEMINI_API_KEY=
```

`GEMINI_API_KEY` 是 Google Gemini 官方接口的密钥；需要代理时设置 `GEMINI_PROXY`（必须带协议），`GEMINI_AUDIO_MODEL` 可覆盖音频模型。出点位默认 `gemini-4-hydrogen`；识别与切分不再调用其他模型。音频不再经过对象存储：窗口裁成 WAV 后直接内联发送，超过 20 MB 时自动改用 Files API 并即时删除。

## 工具操作中心

- **工作台**：选择或拖入音视频，调整执行顺序及参数，上传后提交任务。浏览器上传按实际传输字节显示进度，支持取消、移除和手动重试。同名文件使用独立 ID。
- **链接下载**：填入 yt-dlp 支持的视频链接，按需填写 Cookie 请求头，或读取 Netscape 格式的 `cookies.txt`，点击“下载、合并并切片”。服务负责下载音视频轨、合并封装为 MKV，再执行分析和切片。哔哩哔哩普通视频链接自动将全部分 P 加入队列，带 `?p=2` 等分 P 参数时处理指定的 P，短链接按跳转后的地址处理。各 P 独立保存源文件、进度和结果，某一 P 失败后继续处理后续 P，续跑保留已成功的 P。其他网站按单视频链接处理。下载大小、百分比和合并状态显示在进度区。
- **补齐旧任务的分 P**。此前只处理了 P1 的成功任务，在工作台和历史详情中点击“补齐分 P”，会读取分 P 列表并处理 P2 及后续分 P，保留原 P1 的歌曲、文件和识别结果。该入口适用于仍保留完整任务记录、原始链接没有指定 `p` 参数的哔哩哔哩任务。
- **历史**：独立查看日志、步骤和结果；浏览历史时当前任务仍持续跟踪。手动选择视频后保持选择，可显式点击“跟随当前视频”。
- **用量**：查看本次服务统计、选中任务累计费用、各次执行和实际模型调用记录、按模型明细。任务用量跨服务重启保留，服务累计从本次启动计算。

结果支持页面试听、按片段下载，以及任务结束后下载包含确认片段与 JSON 记录的 ZIP。上传源文件、下载视频、结果、检查点及缓存保留至手动删除。下载 Cookie 仅存于源文件目录的权限 `0600` 文件，接口不返回 Cookie 内容，浏览器不保存 Cookie；删除最后引用的任务时一并清理。

任务与文件保存在 `data/webui/`，可用 `--data-dir` 或 `WEBUI_DATA_DIR` 指定：

| 位置 | 内容 |
| --- | --- |
| `workspace.sqlite3` | 文件、任务、执行次数、结构化步骤、用量及缓存引用 |
| `uploads/<id>/` | 上传或下载源文件，以及下载参数 |
| `jobs/<id>/<视频ID>/` | JSON 记录、片段、检查点、执行日志 |
| `audio/` | 按内容定位的共享提取音频 |

服务运行不依赖页面保持打开。服务重启后未完成任务标记为“执行中断”，点击续跑恢复。旧版 `logs/webui-history.json` 导入为仅摘要的历史记录，会明确提示缺失详情与源文件。

## 任务确认与操作

- 历史支持按文件名或任务 ID 搜索、按状态筛选。页面、任务、面板和筛选条件写入 URL，支持刷新恢复与浏览器前进/后退。
- 任务详情可查看来源、执行次数、时间和处理参数。链接任务区分“复用视频重新分析”与“重新下载原链接”；缺失源文件时禁止复用。
- 中断上传可在原条目重新选择同名、同大小文件后重传；不会冒充断点续传。并发参数统一放在高级设置，非法输入在字段旁显示并阻止提交。
- 结果显示原视频时间范围、文件名及识曲依据，支持查看和下载分析 JSON。任务结束后可以编辑标题、歌手、起止秒数并通过 FFmpeg 重新导出；不调用模型，导出失败保留原结果。编辑后的 JSON 和片段持久保存，整批 ZIP 使用最新结果。
- 日志支持全历史关键词定位、复制、下载与分页浏览；分页仅限制渲染范围，不丢弃历史。用量展示当前执行记录，模型明细可切换任务和本次服务口径。
- 进度默认显示当前工作、其他并行工作的数量及异常，完整步骤与逐项上传记录统一放入“步骤详情”；重复错误合并显示并保留来源。手机提交按钮与桌面使用一致的底部操作区。

## 进度、重试与缓存

进度由独立事件管道传输：批次按视频计数，扫描按分块计数，候选按工作单元计数，FFmpeg 按已处理媒体时长计数，浏览器上传按真实字节计数。未知总量的请求展示状态与耗时，不以固定阶段权重估算时间百分比。并行步骤可同时运行，等待资源、缓存复用、跳过、失败和停止分别展示。

“续跑”保持任务与参数，复用该任务通过校验的成功检查点，仅执行未完成步骤和依赖改变的后续工作。检查点统一以 UTF-8 写入和读取，Windows 续跑不依赖系统代码页。“重新处理”创建新任务，允许调整参数，重新生成模型分析，同时复用匹配的媒体缓存。语义校验失败的模型响应不会提交为成功检查点。

模型音频不经过对象存储：音频窗口裁成单声道 24 kHz WAV 写入任务状态目录，以 base64 内联发送（单次上限 20 MB，更长的窗口自动改用 Files API 并在请求后立即删除）。识别用 mp3 与导出片段按任务状态目录本地缓存，手动删除任务时一并清理。

扫描会明确告知模型输入音频时长和相对秒数范围；分块扫描同时标明核心区间及前后上下文。超出范围或倒置的时间会作为明确错误直接失败并写日志，不会悄悄裁剪成看起来正确的区间。网络与 API 错误直接上报。

扫描由 `gemini-4-hydrogen` 一次给出完整歌曲边界，不再做二次边界精修，也不再有任何模型复核环节：识曲结果直接决定标题与切分。

歌名决定结论，歌手只作展示。Shazam 与网易云歌名一致（繁简、版本后缀归一化后）即直接填入；不一致时标题留空，界面列出各家候选供点选或手动填写。扫描时还会记录主播报幕原话，作为人工判断的参考线索，没有明确报幕时留空。

切分以完整演唱为目标，保留有证据的前奏、尾奏、间奏、换气与短暂插话。模型判断仍可能不准确，JSON 记录保留扫描理由与主播报幕，便于人工核对。

自动切片在跨块去重完成后，将结束点向后延长 2 秒。片段按源视频位置定位：只改标题时复用已导出的视频并改名，不会重新编码，也不会因改名丢失手动修改。遇到下一首起点或源视频结尾时，只延长到该边界。结果中的时间和时长采用实际导出范围，`tail_extension` 记录延长前的结束点与实际延长秒数。续跑重新计算延长范围，手动编辑按填写的时间导出。

## 并发与耗时

视频按队列顺序执行，同一视频内部的独立分块、候选与追加识别并发。Shazam 与网易云在同一运行事件循环中并发；阻塞的 FFmpeg、同步模型与网易云工具调用在工作线程执行。音频提取和导出共享媒体资源额度。候选结果由单一协调器按稳定顺序提交 JSON。

| 参数 | 默认 |
| --- | --- |
| 扫描并发 | 3 |
| 候选处理并发 | 3 |
| 模型请求并发 | 3 |
| 识曲请求并发 | 3 |

| 媒体进程并发 | CPU 数与 2 的较小值 |

前端高级设置可调整额度及分块时长。每步记录实际耗时、等待资源耗时和复用状态；调用与上传记录可用于对照串行设置。单视频速度取决于媒体长度、CPU、网络和上游响应，不能仅凭调度并发数推断收益。

所有实际模型请求（包括失败及 JSON 重试）都记账；检查点复用不产生新调用。无效 JSON 默认额外重试 3 次，可通过 `MUSIC_AGENT_JSON_RETRIES=0` 禁用；请求失败明确结束，不隐藏错误。费用按 Gemini 官方美元价估算，未知价格或缺失 usage 会标记统计不完整。

模型返回的 usage token 数值无效时，跳过该次 token 和费用统计，保留调用次数并标记用量缺失，记录一条简短警告，任务继续执行。

用量以事件流形式记录，子进程通过独立管道回传，不写入普通日志。

## 网易云识曲

`vendor/ncm-afp/audio_match.js` 从 NeteaseCloudMusicApi 4.32.0 的音频匹配路由提取，使用 Node 自带 fetch 直接请求网易云上游，不依赖 axios、Web 服务器或整包 npm 安装。来源和 MIT 许可见同目录 README 与 LICENSE。

Python 提取 8 kHz Float32 PCM，打包的指纹工具生成 audioFP，再通过标准输入向匹配工具传递指纹、超时和 Cookie。Node 子进程的标准输入和输出明确使用 UTF-8，不依赖 Windows 系统代码页。无匹配、异常响应、HTTP 错误和超时分别明确处理。可通过服务端 `MUSIC_AGENT_NETEASE_COOKIE` 配置网易云 Cookie，与下载视频的 Cookie 独立。

同一片段从 6、12、20、30 秒处各取一段识别，按归一化歌名多数决：cover、伴奏、纯享版等版本附注算同一票，平票才标记冲突，由人工在界面选择或填写。起点位置会影响结果，因此不能只取首个命中。

采样点串行执行，`--recognizer-timeout` 同时是整体时限：单点超时按剩余时间裁剪，用时耗尽后跳过剩余采样点并沿用已有结果，避免慢网络下累计等待数倍超时。

## 界面与构建

固定使用 `@material/web@2.5.0`。按钮、图标按钮、列表使用该版本 `labs/gb` 的 Expressive 工具实现；输入、开关、标签页、进度条与对话框使用 M3 组件。蓝紫主题由 `#3f5ad4` 生成，浅深色均使用本地字体与 SVG 图标，无外部字体请求。

桌面达到 1280px 时三栏，840–1279px 双栏，更窄时单栏及面板标签；手机使用底部导航。键盘可通过 Tab 操作，`Alt+1/2/3` 切换区域，系统减少动态效果模式取消位移。

```bash
cd webui
npm ci
node scripts/theme.mjs   # 需要重新生成主题时使用
npm run typecheck
npm run release         # 正式构建并复制到 segment/webui_dist
```

Python 直接托管静态产物，运行时不需要 Next.js 服务。发布产物随仓库保留。

## 命令行与 Docker

```bash
uv run -m segment.music_agent.cli --media video.mp4 --outdir output
uv run -m segment.music_agent.cli --help

docker compose -f compose.api.yaml up --build -d
docker compose -f compose.api.yaml logs api
```

Compose 仅启动一个应用容器，挂载 `data/webui/` 和 `logs/`，不需要单独的网易云容器。控制台日志提供带令牌地址；停止容器不删除持久化数据。CLI 与 WebUI 共用 API 管线和后端环境配置。
